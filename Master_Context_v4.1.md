# Master Context v4.1: Universal 1C Furniture Data Normalizer & WMS Bridge

## 1. Executive Summary & Business Context
* **Цель проекта:** Создание ETL-движка нормализации данных, устраняющего разрыв между печатными формами заказов 1С 7.7 и складской WMS-системой на ТСД (SQLite) на складе в г. Челябинск.
* **Суть проблемы на складе:**
  1. **Приемка:** На коробках есть только фабричный **Штрихкод (EAN-13)**. Кладовщик сканирует его и привязывает к локальной ячейке челябинского склада в WMS.
  2. **Сборка (Узкое место):** Отборочные листы из 1С 7.7 приходят в виде визуальных бланков без штрихкодов с искаженными названиями. WMS не может сопоставить текст, не находит **Штрихкод** и не может выдать сборщику ячейку на ТСД.
* **Решение:** Продукт парсит кривую отборочную 1С 7.7, извлекает заказчика, выполняет гибридное сопоставление с каталогом фабрики (1С v8 на 10k+ строк), восстанавливает заводские **Штрихкоды (EAN-13)** и выдает чистый 4-колоночный файл для штатного импорта в WMS склада.

## 2. Dual-Engine LLM Architecture (Cloud Dev -> Offline Prod)

Движок сопоставления использует гибридный Fallback для сложных случаев (стекла, коллизии):

* **Режим разработки (Development):** 
  - Провайдер: **Google AI Studio API**
  - Модель: `gemini-2.0-flash` (или `gemini-1.5-flash`)
  - Быстрый отклик, бесплатный лимит, строгий Structured Output JSON.
* **Режим продакшена на складе (Production / Offline Russia):**
  - Провайдер: **Локальная Open-Source модель через Ollama**
  - Модель: `qwen2.5:7b` (или `llama3.2:3b`)
  - 100% автономность без доступа к внешнему интернету, нулевой риск гео-блокировок.
* **Векторная база:** Локальная модель `multilingual-e5-small` + `FAISS` (работает автономно на CPU без сети).

Dynamic Knowledge Base: При старте скрипт извлекает уникальные множества KNOWN_MODELS, KNOWN_COLORS, KNOWN_MATERIALS из каталога v8. Хардкод в коде запрещен.
Hard Constraints (Защита от пересорта):
Номер упаковки (Упаковка) обязан совпадать на 100% (2/2 отсекает 1/2).
Извлеченные размеры (\d+[хx*]\d+) отсекают несовпадающие габариты.
Тип Стекло фильтрует позиции по столбцам Начинка и ТипЭтикетки с проверкой толщины (4мм vs 5мм).
Semantic Vector Search: Вычисляет косинусное сходство между строкой заказа (клиентский текст + желтый алиас) и номенклатурой каталога через multilingual-e5-small + FAISS.

6. Non-Negotiable Engineering Guardrails
Строгая строковая типизация: НоменклатураКод и Штрихкод никогда не приводятся к int/float. Чтение и запись выполняются strictly as str.
Корректное чтение Excel: Восстановление больших чисел (2,006E+12 -> строковый 2006000045445).
Автономия при разработке:
Локальные файлы лежат в /data/ (не передаются в контекст целиком).
Тестирование использует цветные CLI-логи (rich), Excel Diff-отчеты «До/После» и легковесный локальный дашборд на Streamlit.
